## A. バグ・問題点

### 重要度: 高

- [x] **A-1. 生 `BEGIN`/`COMMIT` の失敗時にトランザクションが残留し、以後の書き込みが全滅する**
  - 対象: `core/tags.rs` 121–131(`tag_videos`)・146–156(`untag_videos`)・363–371(`reorder_tag_groups`)、`core/series.rs` 53–65・81–98、`core/library.rs` 234–243(`scan_folder`)・323–330(`register_paths`)、`core/smart_folders.rs` 93–101、`core/fileops.rs` 146–176(`apply_relink`)、`commands/maintenance.rs` 257–265、`core/playlists.rs` 219–229(`reorder`)
  - `conn.execute_batch("BEGIN")?; …?; conn.execute_batch("COMMIT")?` の形は、途中の文が失敗(SQLITE_BUSY のタイムアウト超え、外付け HDD の I/O エラー、ディスクフル等)すると ROLLBACK されずに `Err` で抜ける。共有の長寿命コネクションなので、以後の `BEGIN` は「cannot start a transaction within a transaction」で全部失敗し、トランザクションを張らない書き込み(`set_rating` 等)は開いたままのトランザクションに吸い込まれ、**成功に見えて終了時に静かに巻き戻る**。MCP という別プロセスの書き込み経路が実在するので busy 競合は現実に起きる。`videos.rs` の `mark_opened`(169 行)は自らこの危険をコメントで認識して `unchecked_transaction` を使っており、他が揃っていないだけ
  - 修正案: すべて `conn.unchecked_transaction()?`(drop で自動 ROLLBACK)+ `tx.commit()?` へ機械的に置換

- [x] **A-2. 「キューを置き換えて再生」が上限超過時に既存キューを消す**
  - 対象: `src/components/VideoGrid.tsx` 220–227
  - `replace` 分岐だけ `addToQueue` の `overflow` を見ていない。選択は最大 1000 件まで可能なので、501 件以上選んで置き換えると `addToQueue(EMPTY_QUEUE, videos)` が `{queue: EMPTY_QUEUE, added: 0, overflow: true}` を返し、**手で並べた既存キューが空に置き換わる**(dirty=false なので終了時の保存確認も出ない=完全消失)。さらに「再生できる動画がありません」という事実と違うトーストが出る。212 行のコメント「上限に当たったときは部分的に入れず全部断る」に反している
  - 修正案: `replace` 分岐でも `overflow` を確認し、true なら既存キューに触れず 232 行と同じトーストで return

- [x] **A-3. キュー端の missing/offline 動画を「飛ばした」と言いながら再生してしまう**
  - 対象: `src/components/player/usePlayQueue.ts` 76–87
  - スキップ処理が `s.playFromQueue(next)`(=再生対象を missing 動画に設定)**してから**再帰する。キューの端が missing だと再帰が `queueStep === null` で止まり、missing 動画が再生対象のまま残って mpv が欠損ファイルを load → 失敗 → WebView2 エンジンへフォールバック → そこでも失敗、とエラートーストが連鎖する。キューモードは常に自動送りなので、**最後の 1 本がオフライン HDD 上にあるだけで前の動画が終わった瞬間に発生**する。外付け HDD / NAS 前提のこのアプリでは現実的に踏む
  - 修正案: 状態を変えずにループで「次の再生可能な 1 件」を探し、見つかったときだけ `playFromQueue` を 1 回呼ぶ。1 件も無ければトーストのみで現状維持

- [x] **A-4. ストア全体購読により、あらゆる更新でアプリ全ツリーが再レンダーされる**
  - 対象: `App.tsx` / `VideoGrid.tsx` / `Sidebar.tsx` / `Toolbar.tsx` / `Inspector.tsx` / `FilterBar.tsx` / `FolderTree.tsx` / `TagTree.tsx` / `MpvPlayerView.tsx` / `PlayerOverlay.tsx` / `StatsModal.tsx` / `HistoryModal.tsx` ほか計 16 か所のセレクタなし `useLibrary()`
  - Zustand v5 ではセレクタなしはストア全体を返すため、どのフィールドが変わっても再レンダーされる。ルートの App までこのパターンで、`VideoCard` / `VideoListRow` は `React.memo` なし。具体的に痛いトリガー: スキャン中の `scan:state`(取り込み中ずっと)、字幕スタイルのスライダードラッグ(再生中に毎入力イベント)、トースト、矢印キーでの選択移動(1 キーごと)
  - 修正案: まず App / VideoGrid / Sidebar / Toolbar / Inspector / FilterBar の 6 つを `useLibrary((s) => s.xxx)` + `useShallow` に移行し、`VideoCard` / `VideoListRow` を `React.memo` 化

## B. 実機 UI 確認の結果

確認環境: dev 起動中の実アプリに CDP + Playwright で接続し、キュー / プレイリストの一連の操作を実行。mpv の映像はデスクトップ実キャプチャで確認。

**動作 OK を確認したもの:**
- キューパネル(右ペインタブ・件数 2/500・行のサムネイル/時間/×・ドラッグハンドル・現在行のハイライト)
- 右クリックメニュー「キュー」サブメニュー(追加 / 次に再生 / 置き換えて再生)
- キューからの再生開始、**自動送り**(1→2 へ進み、末尾で停止してプレイヤーは開いたまま)
- ⏭ ツールチップに「次の動画: <ファイル名> (N)」、コントロールバーのキュー位置「1 / 2」
- 再生速度メニュー 0.25x〜4x の 11 段
- プレイヤー内キューパネル(Q キーで開閉、コンパクト表示、映像の上に重なって表示)
- 名前を付けて保存 → トースト → サイドバー「プレイリスト」セクションに即反映 → パネルのタイトルがリスト名に変わる
- プレイリストの右クリックメニュー(キューに読み込んで再生 / このリストで絞り込む / 名前を変更 / 複製 / 削除)と、削除のネイティブ確認ダイアログ
- Esc の 2 段階(プレイヤー内パネルを閉じる → プレイヤーを閉じる)。閉じた後の絞り込み・スクロール位置の保持

**実機で見つけた気づき:**
- A-28 の実証: プレイリスト削除後もキューのタイトルが旧名のまま(上記)
- プレイリスト 0 件のときサイドバーに「プレイリスト」セクション自体が出ない。機能の存在に気づく入口が右クリックメニューと Q キーだけなので、空でも見出し+「キューから保存できます」の 1 行を出す選択肢はある(好みの問題)
